# MediaView

适用于 macOS 13 及以上版本的本地图片和视频查看器。

- **图片**：JPEG、PNG、HEIC/HEIF、GIF、TIFF、WebP，以及系统支持的 RAW 格式。
- **视频**：MP4、MOV、M4V，具体编码支持取决于 macOS。

## 使用

将文件或文件夹拖入窗口，或按 `⌘O` 打开。默认包含子文件夹，可在「查看 → 包含子文件夹」中关闭。

- **浏览**：`←` 和 `→` 切换文件，`⌘F` 按文件名查找，`⌘I` 查看文件信息。
- **看图**：滚动或双指捏合缩放，`⌘0` 适合窗口，`⌘1` 显示原始尺寸。图片超出窗口时，按住左键直接拖动；也可按住空格从留白处拖动。
- **看视频**：打开后停在首帧，按空格播放或暂停。

## 选片打印

打开照片文件夹，选择菜单栏的 **选片 → 开始选片**（`⇧⌘P`）。选片范围包含该文件夹及子目录中的图片，可随时退出并继续普通浏览。

- **逐张筛选**：点击“入选”或按 `P`，点击“跳过”或按 `X`；`U` 恢复待选。跳过只做标记，保留原文件。默认标记后自动下一张，可关闭。
- **纠正与复核**：`⌘Z` 撤销并回到刚才的照片，`⇧⌘Z` 重做。顶部可切换全部、待选、入选、跳过；入选页提供网格，点击照片查看大图，“移出入选”会恢复为待选。
- **分次完成**：选片记录自动保存在本机，重新打开同一文件夹并进入选片即可继续。保存失败时点击“重试”；目录移动或改名后会作为新的选片目录处理。
- **导出原图**：点击“导出入选”或按 `⇧⌘E`，选择保存位置。应用新建入选照片文件夹并复制原文件，保留格式和元数据，同名副本自动添加序号。导出进度可取消，已完成的副本保留；完成后可在 Finder 中查看，也会列出缺失或复制失败的文件。

导出保留原文件内容，预览中的旋转、镜像不会写入副本。相册排版、照片顺序和打印格式可在后续使用的排版软件中安排。

## 检查重复照片与视频

打开文件夹，选择菜单栏的 **文件 → 检查重复照片与视频…**。检查范围包含当前文件夹及全部子目录，不改变普通浏览的子目录设置。

- **分组核对**：完全重复表示整个文件内容相同，改名也能识别；疑似重复用于压缩、改分辨率、改格式或转码后的同一素材。照片可放大查看，视频会比较多个时间点，复核时可播放核对画面和声音。
- **自行选择保留版本**：默认不勾选任何清理项。可逐项勾选“待清理”，或选择“保留此版本”勾选其余副本；每组至少保留一份。点击“移到废纸篓…”后还会展示实际文件清单，确认后才移动。
- **分次复核**：保留选择、待清理勾选、忽略组和查看位置自动保存在本机。重新进入会先检查文件是否变化，再恢复仍有效的决定；变化的组需要重新核对。保存失败可以重试。
- **中途取消与失败**：检查和清理均可取消；清理取消后，已经移到废纸篓的文件仍在那里。无法读取、被替换或移动失败的文件会列在“查看问题”中。操作前还会检查保留件是否仍有效。
- **与选片配合**：检查时暂存原来的浏览或选片状态，返回后继续原位置。已入选照片带有标记；若仍选择清理该文件，原选片记录会显示文件缺失，不会自动把标记转移给另一个版本。

所有分析在本机完成。疑似检查采用保守的画面匹配，不判断裁剪、水印、滤镜或视频片段是否同源，也不比较音频指纹；多帧图片只参与完全重复检查。

## 构建

在 macOS 上使用 Swift 6 或更高版本，从仓库根目录执行：

| 版本 | 构建命令 | 产物 |
| --- | --- | --- |
| 本机 Debug | `swift build -c debug` | 调试用可执行文件 |
| 本机 Release | `swift build -c release` | 优化后的可执行文件 |
| 通用版（Apple Silicon 和 Intel） | `./Scripts/build-universal.sh` | `build/MediaView.app` |
| Apple Silicon | `./Scripts/build-universal.sh --arch arm64` | `build/arm64/MediaView.app` |
| Intel | `./Scripts/build-universal.sh --arch x86_64` | `build/x86_64/MediaView.app` |
| DMG 安装包 | `./Scripts/build-dmg.sh --arch arm64 --version 1.2.3`（Intel 改用 `x86_64`） | `build/release/MediaView-1.2.3-<arch>.dmg` |

本机运行：`swift run MediaView`。运行测试：`./Scripts/test.sh`。本地签名与公证选项见 `./Scripts/build-universal.sh --help`。

## 发布

先将待发布的改动提交到 `main`，再推送分支和新的稳定版标签（以 `v1.2.3` 为例）：

```sh
git push origin main
git tag v1.2.3 main
git push origin v1.2.3
```

自动发布只响应新建的 `vX.Y.Z` 标签。测试通过且 Apple Silicon 和 Intel 的 DMG 均通过校验后，两个安装包会随 GitHub Release 一起发布。

若标签已推送但 Actions 没有运行记录，可在 **Actions → Release macOS installers → Run workflow** 中选择 `main`，填写已有标签（例如 `v1.0.0`）进行补发。补发会解析并固定标签原有的提交，使用它测试和打包；所选工作流分支的新代码不会混入该版本。已有运行记录的失败任务也可以直接在 Actions 中重跑。

安装包使用 ad-hoc 签名，未经 Apple 公证，首次打开可能出现 macOS 安全提示。补发和重跑都不会覆盖已公开的附件。
